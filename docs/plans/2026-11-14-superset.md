# 补齐易支付功能：契约与分工

目标：让 GorixPay 在功能上 ⊇ 彩虹易支付。判定标准是 `docs/epay-coverage.md` 里每一条「部分实现」「未实现」都变成「已实现」，或者写明不适用并给出理由。

这份文档只写**协作契约**：谁的迁移号、谁的包、接口长什么样、谁不能碰哪个文件。实现细节各人自己决定。

## 共同规则

- **迁移号已分配，不要抢**。只能新建自己编号的文件，不能改别人和历史的迁移。
- **路由各自注册**。每个模块在自己的包里提供 `Register(group *gin.RouterGroup, ...)`，Lead 在 `internal/platform/app/app.go` 里接线。**不要改 `internal/admin/httpapi/handler.go`**（那是别人的文件，改了就冲突）。
- **前端不要动 `router/index.ts`、`api/index.ts`、`api/types.ts`、`stores/*`**。新增 API 用新文件（如 `api/groups.ts`）；路由清单在报告里交给 Lead 统一加。
- 分页一律 `page` + `page_size`，返回 `{items,total,page,page_size}`；`pagination(ctx)` 有现成的（自己包里抄一份也行）。
- 金额一律 int64 分；时间 UTC；错误统一 `400 invalid`、`401`、`404`、`409` 语义。
- 每个模块都要有单元测试（真实 SQLite + httptest），`go test ./<自己的包>/...` 通过，`gofmt -l` 干净。
- 不引入新的第三方依赖，除非能说清为什么。

## M1 用户组与费率（backend-migrate）

迁移 `000017_group_fees.sql`：
- `merchant_groups(id, name, rate_bp int, pay_types text, settle_mode text, status, created_at, updated_at)`
- `merchants.group_id`（可空，外键到 merchant_groups）、`merchants.settle_mode`（`normal` / `direct`，默认 `normal`）

包 `internal/merchantgroup`：`model.go`、`service.go`、`http.go`、测试。
接口（管理员）：
- `GET /api/v1/admin/groups` 列表
- `POST /api/v1/admin/groups` 创建 `{name, rate_bp, pay_types[], settle_mode}`
- `PUT /api/v1/admin/groups/:id` 更新
- `PATCH /api/v1/admin/groups/:id/status` `{status}`
- `DELETE /api/v1/admin/groups/:id`（有商户引用时 409）
- `PATCH /api/v1/admin/merchants/:id/group` `{group_id}`（`null` 表示移出组）

给别人的唯一入口：`func (s *Service) RateBp(ctx, merchantID) (int, bool)`，返回商户所属组的费率（万分比），未分组返回 `(0,false)`。结算模块按它算手续费。

## M2 结算自动化（backend-v2）

迁移 `000018_settlement_auto.sql`：
- `settle_rules(id, name, merchant_id nullable, min_amount_cents, fee_bp, period, auto_transfer bool, status, last_run_at, created_at, updated_at)`
- `settlements` 新增 `source`（manual/auto）、`fee_cents`、`transfer_status`（none/pending/done/failed）、`transfer_at`

包 `internal/settlement`：`rule.go`、`service.go`、`http.go`、测试。**不要改 `internal/finance`**，通过它的公开方法建结算单。
- `RunAutoSettle(ctx, now)`：按 active 规则挑出可结算商户（可用余额 − 冻结 ≥ `min_amount_cents`），手续费 = 金额 × 费率（费率来自注入的 `FeeResolver`，M1 提供），生成结算单（`source=auto`），同一天同一商户只生成一张（幂等键 `auto-settle:{ruleID}:{merchantID}:{yyyymmdd}`）。
- `AutoTransfer(ctx, settlementID)`：结算单审核通过且规则 `auto_transfer=true` 时，调 `internal/transfer` 的现有 `Create` 创建代付单；商户没有结算资料就跳过并把 `transfer_status` 置 `failed`、写原因。
- 调度：`func (s *Service) Start(ctx, interval)` 起 ticker，`sync.Map` 防重入；多副本靠 `settle_rules.last_run_at` 的条件更新只让一个跑。
接口：
- `GET/POST/PUT/DELETE /api/v1/admin/settle-rules[/:id]`
- `POST /api/v1/admin/settle-rules/:id/run` 手动跑一次，返回生成数量
- `POST /api/v1/admin/settlements/batch-process` `{ids[], action: approve|reject, reason}`
- `GET /api/v1/admin/settlements/:id` 已有，别重复注册

## M3 分账与红包（backend-plugins）

迁移 `000019_profit_sharing.sql`：
- `profit_sharing_receivers(id, merchant_id, receiver_type, account, name, rate_bp, status, created_at, updated_at)`
- `profit_sharing_orders(id, order_id, merchant_id, receiver_id, amount, status, ledger_transaction_id, channel_batch_no, error, created_at, updated_at)`
- `transfer_orders` 新增 `kind`（`normal` / `red`）

包 `internal/profitsharing`：
- 接收方 CRUD（商户自助 + 管理员代管）
- 规则：按 `rate_bp` 对订单金额分账，保留两位分（向下取整），平台手续费先扣
- 执行：`Execute(ctx, orderID)` 在订单支付成功后按接收方生成分账记录；内部接收方直接走账本（`split:{orderID}:{receiverID}` 幂等），`pending` 状态给需要渠道分账的留口子
- 接口：`GET/POST/PATCH /api/v1/merchant/profit-sharing/receivers`，`GET /api/v1/merchant/profit-sharing/orders`，管理员同构 `/api/v1/admin/profit-sharing/*`，`POST /api/v1/admin/profit-sharing/orders/:id/retry`

红包（`internal/transfer` 里加，**这个包归你**）：
- `CreateRed(ctx, req)`：一次创建 N 个红包代付单（`kind=red`），金额随机分配且合计等于总额，最少 1 分
- 接口：`POST /api/v1/merchant/transfers/red`、`POST /api/v1/admin/transfers/red`

## M4 导出与统计（backend-ops）

无迁移。包 `internal/reporting`：`csv.go`、`stats.go`、`http.go`、测试。
- 导出（CSV，UTF-8 BOM，`Content-Disposition: attachment`）：`GET /api/v1/admin/export/{orders|refunds|settlements|transfers|merchants|ledger}.csv`，支持与列表页相同的过滤参数；商户侧 `GET /api/v1/merchant/export/{orders|records}.csv`
- 统计：`GET /api/v1/admin/stats/buyers`（按买家/付款人聚合：笔数、金额、首末时间）、`GET /api/v1/admin/stats/merchants`（商户维度：订单数、支付金额、退款金额、手续费估算）、`GET /api/v1/merchant/stats/daily`
- 商户资金明细：`GET /api/v1/merchant/records` 读账本分录（`ledger_entries` join `ledger_transactions`），返回 `{items,total,...}`，字段：`created_at,type,amount,direction,balance_after,reference`。

## M5 前端运营端（fe-admin）

新增页面（路由清单交给 Lead）：
- `/admin/groups` 用户组：列表、新建/编辑弹窗（名称、费率 bp、可用支付方式、结算模式）、启用禁用、删除
- `/admin/settle-rules` 结算规则：列表、新建/编辑、手动执行按钮（显示生成数量）、自动打款开关
- `/admin/profit-sharing` 分账：接收方列表 + 分账流水
- `/admin/reports` 报表：买家统计、商户统计两张表 + 导出按钮（下载 CSV）

API 函数放新文件（`api/groups.ts`、`api/settleRules.ts`、`api/profitSharing.ts`、`api/reports.ts`），**不要动 `api/index.ts`、`api/types.ts`、`router/index.ts`**。
